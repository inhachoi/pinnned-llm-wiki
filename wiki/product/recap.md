# 리캡

## 흐름

1. 지도의 Recap 버튼을 누르면 이미지 추출 화면으로 간다 (SPEC-14 §1)
2. 팟 이름 아래 설명 툴팁과 리캡 이미지 미리보기를 본다 (SPEC-14 §3, §4)
3. [이미지로 내보내기]를 누른다. 이후 동작은 두 원문이 다르게 적는다 (SPEC-14 §5, SPEC-15 §3)
4. 결과를 토스트로 본다 (SPEC-14 §6, §6-1)
5. 뒤로가기는 이전 화면(홈)으로 간다 (SPEC-14 §2)

## 규칙

### 화면

- 설명 툴팁 문구는 "{국가명}에서 {총 여행 지역 수}개의 핀을 만들었어요"다 (SPEC-14 §3, SPEC-15 §1)
- 국가명은 MVP 기준 "대한민국"이다 (SPEC-15 §1)
- 핀 개수 N은 "팟이 꽂은 핀(장소) 총 개수"라고 적혀 있다 (SPEC-15 §1)
- 미리보기는 실제로 저장·공유될 이미지를 화면 중앙에 보인다 (SPEC-14 §4)
- 상단 프로필 순서는 나 → 방장 → 팟 참여 순서다. 가장 나중에 들어온 사람이 맨 끝이다 (SPEC-15 §1)

### 리캡 카드

- 카드는 여행 통계 + 지도를 담은 내보내기용 이미지다 (SPEC-15 §2)
- 상단 타이틀은 툴팁과 같은 내용을 다른 디자인으로 쓴다. 예: "10 PINNNED / in KOREA" (SPEC-15 §2)
- 지도는 현재 팟 홈 화면 지도와 같은 소스를 쓰고 카드 비율에 맞게 크기만 조정한다 (SPEC-15 §2)
- 핀 색상과 키워드 이모지 매핑은 홈 화면 로직을 그대로 유지한다 (SPEC-15 §2)
- 카드 좌측에 같은 팟 멤버의 닉네임을 태그 형태로 전부 보인다 (SPEC-15 §2-1)
- 닉네임 라벨 순서는 나 최상단 고정 → 방장 → 팟 참여 순서다 (SPEC-15 §2-1)
- 여행지를 1~5개 등록했으면 도별로, 6개 이상이면 시별로 보인다 (SPEC-15 §5)
- 도별 표시는 기존 도별 디자인을 그대로 쓴다 (SPEC-15 §5)

### 스토리용 이미지

- 스토리용 비율이며 그 비율로 다운로드돼야 한다 (SPEC-15 §4)
- 텍스트는 상단에 팟 이름, 하단에 팟원 닉네임 라벨이다. 라벨 규칙은 리캡 카드와 같다 (SPEC-15 §4)

### 내보내기

- 한 원문은 버튼 클릭 시 현재 미리보기 이미지를 기기에 저장 시도한다고 적는다 (SPEC-14 §5)
- 다른 원문은 버튼 클릭 시 OS 기본 공유 시트를 띄우고 사용자가 카메라 롤에 저장할 수 있다고 적는다 (SPEC-15 §3)
- 사진 접근 권한이 없으면 접근 권한 비허용 팝업을 보인다 (SPEC-14 §5)
- 저장 성공 시 성공 토스트를 3초 보인다 (SPEC-14 §6)
- 저장 실패 시(권한 거부, 저장 공간 부족 등) 실패 토스트를 3초 보인다 (SPEC-14 §6-1)

## 확인 필요

- 닉네임 라벨을 "최대 6명, 인원 제한 없이 전부 표시"라고 적는다. 정원이 6명이라 결과는 같지만 문장이 엇갈린다 (SPEC-15 §2-1)
- "방장"은 리캡 원문에만 나온다. 다른 원문의 팟장과 같은 뜻인지 확인 필요 (SPEC-15 §1, §2-1)
- 멤버 순서가 리캡은 나 → 방장 → 참여순, 다른 화면은 나 → 가입순이다. 내가 방장이 아닐 때 순서가 달라진다. 의도인지 확인 필요 (SPEC-15 §1)
- 성공·실패 토스트의 문구는 사본에 없다 (SPEC-14 §6, §6-1)
- 리캡 카드와 스토리용 이미지가 별개 산출물인지, 미리보기에 어느 쪽이 보이는지 원문에 없다 (SPEC-14 §4, SPEC-15 §2, §4)
- 기록이 0개인 팟의 리캡 진입·표시는 원문에 없다 (SPEC-14 §1)
- 기준 페이지의 `리캡 B안 — 사진 콜라주 (시안)`은 확정 전이라 이 쪽의 근거가 아니다. [Figma 기준 페이지](../design/figma-baseline.md) 참고
